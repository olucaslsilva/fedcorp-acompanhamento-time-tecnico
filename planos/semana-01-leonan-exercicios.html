Semana 1: Refatoração

Leonan Thomaz de Oliveira. Python / FastAPI. Tempo estimado: 5 a 7 horas.

O que é refatoração: é reorganizar um código que já funciona, sem mudar o que ele faz, para que fique mais fácil de ler, manter e evoluir. Pense em um armário bagunçado: tudo está lá dentro, mas encontrar algo demora. Refatorar é organizar esse armário.

Conceitos com exemplos

1. Nomes descritivos

O nome de uma variável ou função deve dizer exatamente o que ela faz ou guarda. Se alguém ler o nome e precisar abrir a função pra entender, o nome está ruim.

# Ruim: o que é "d"? O que é "proc"? Ninguém sabe sem ler o código inteiro
def proc(d):
    r = d["v"] * 0.9
    return r

# Bom: lendo o nome da função e dos parâmetros, você já entende tudo
def calcular_preco_com_desconto(produto: dict) -> float:
    preco_final = produto["valor"] * 0.9
    return preco_final

2. Funções pequenas com uma responsabilidade

Uma função deve fazer uma coisa só. Se ela valida dados, calcula imposto E salva no banco, ela está fazendo três coisas. Separe em três funções.

# Ruim: uma função gigante que faz tudo
def criar_pedido(dados):
    # valida
    if not dados.get("cliente"):
        return {"erro": "cliente obrigatório"}
    if not dados.get("itens") or len(dados["itens"]) == 0:
        return {"erro": "precisa ter itens"}
    # calcula
    total = 0
    for item in dados["itens"]:
        total += item["preco"] * item["qtd"]
    imposto = total * 0.15
    total_final = total + imposto
    # salva (imagina 20 linhas de SQL aqui)
    db.execute("INSERT INTO pedidos...")
    return {"total": total_final}

# Bom: cada função faz UMA coisa
def validar_pedido(dados: dict) -> None:
    if not dados.get("cliente"):
        raise ValueError("Cliente é obrigatório")
    if not dados.get("itens"):
        raise ValueError("Pedido precisa ter pelo menos um item")

def calcular_total(itens: list, aliquota: float = 0.15) -> float:
    subtotal = sum(item["preco"] * item["qtd"] for item in itens)
    return subtotal + (subtotal * aliquota)

def salvar_pedido(pedido: dict) -> int:
    return db.execute("INSERT INTO pedidos...")

3. Eliminar código repetido

Se o mesmo bloco de código aparece em mais de um lugar, extraia para uma função. Se precisar mudar a lógica, vai mudar em um lugar só.

# Ruim: validação copiada e colada em dois lugares
@app.post("/clientes")
def criar_cliente(data: dict):
    if not data.get("email") or "@" not in data["email"]:  # aparece aqui
        return {"erro": "email inválido"}
    ...

@app.put("/clientes/{id}")
def atualizar_cliente(id: int, data: dict):
    if not data.get("email") or "@" not in data["email"]:  # e aqui também
        return {"erro": "email inválido"}
    ...

# Bom: Pydantic valida automaticamente nos dois endpoints
from pydantic import BaseModel, EmailStr

class ClienteBase(BaseModel):
    nome: str
    email: EmailStr  # valida formato de email automaticamente

@app.post("/clientes")
def criar_cliente(cliente: ClienteBase):  # validação automática
    ...

@app.put("/clientes/{id}")
def atualizar_cliente(id: int, cliente: ClienteBase):  # mesma validação
    ...

4. Separar em arquivos por responsabilidade

Quando tudo está em um arquivo só, qualquer mudança no código pode afetar qualquer parte. Separar em arquivos isola as responsabilidades: quem cuida dos dados fica em um arquivo, quem cuida das rotas fica em outro, quem cuida da lógica fica em outro.

meu_projeto/
├── main.py              # só inicia o app e registra as rotas
├── schemas/
│   └── cliente.py       # define a forma dos dados (Pydantic)
├── routers/
│   └── clientes.py      # recebe as requisições HTTP
├── services/
│   └── cliente_service.py   # regras de negócio
└── repositories/
    └── cliente_repo.py  # fala com o banco de dados

1 Exercício Fácil: Nomes e funções pequenas Fácil

Refatore o código abaixo. Não mude o que ele faz, só melhore a organização.

# Arquivo: exercicio1_antes.py
# Sistema de cálculo de frete (tudo bagunçado)

def calc(p, d, t):
    if t == "normal":
        v = p * 0.05
    elif t == "expresso":
        v = p * 0.12
    elif t == "gratis":
        if p > 200:
            v = 0
        else:
            v = p * 0.05
    else:
        v = p * 0.05
    if d > 500:
        v = v + 15
    return round(v, 2)

# Testes rápidos
print(calc(100, 200, "normal"))    # deve dar 5.0
print(calc(100, 600, "expresso"))  # deve dar 27.0
print(calc(300, 100, "gratis"))    # deve dar 0

O que fazer:

  • Renomear a função e os parâmetros para nomes que façam sentido
  • Separar a lógica de "calcular taxa por tipo" em uma função própria
  • Separar a lógica de "adicionar custo por distância" em outra função
  • Os testes rápidos devem continuar funcionando com os mesmos resultados

Entregar: exercicio1_antes.py (código original) e exercicio1_depois.py (código refatorado)

2 Exercício Intermediário: Eliminar repetição com Pydantic Intermediário

O código abaixo é uma API FastAPI de gerenciamento de funcionários. Funciona, mas tem validação repetida, nomes confusos e tudo num arquivo só. Refatore.

# Arquivo: exercicio2_antes.py
from fastapi import FastAPI
app = FastAPI()

funcionarios = []
next_id = 1

@app.post("/func")
def add(d: dict):
    global next_id
    if not d.get("nome") or len(d["nome"]) < 2:
        return {"e": "nome invalido"}
    if not d.get("cargo"):
        return {"e": "cargo obrigatorio"}
    if not d.get("salario") or d["salario"] <= 0:
        return {"e": "salario invalido"}
    f = {"id": next_id, "nome": d["nome"], "cargo": d["cargo"], "salario": d["salario"], "ativo": True}
    funcionarios.append(f)
    next_id += 1
    return f

@app.get("/func")
def listar():
    return funcionarios

@app.put("/func/{id}")
def edit(id: int, d: dict):
    for f in funcionarios:
        if f["id"] == id:
            if not d.get("nome") or len(d["nome"]) < 2:   # repetido!
                return {"e": "nome invalido"}
            if not d.get("cargo"):                         # repetido!
                return {"e": "cargo obrigatorio"}
            if not d.get("salario") or d["salario"] <= 0:   # repetido!
                return {"e": "salario invalido"}
            f["nome"] = d["nome"]
            f["cargo"] = d["cargo"]
            f["salario"] = d["salario"]
            return f
    return {"e": "nao achei"}

@app.delete("/func/{id}")
def rm(id: int):
    for f in funcionarios:
        if f["id"] == id:
            funcionarios.remove(f)
            return {"ok": True}
    return {"e": "nao achei"}

O que fazer:

  • Criar um schema Pydantic (FuncionarioCreate) para eliminar toda validação manual
  • Renomear as funções e rotas para nomes claros (/func vira /funcionarios)
  • Usar HTTPException do FastAPI em vez de retornar dicts de erro
  • Separar em dois arquivos: schemas.py e main.py

Entregar: exercicio2_antes.py, exercicio2_schemas.py, exercicio2_main.py

3 Exercício Avançado: Arquitetura em camadas completa Avançado

Agora o desafio completo. O código abaixo é uma API de gerenciamento de produtos com estoque. Refatore em 4 camadas: schemas, routers, services e repositories.

# Arquivo: exercicio3_antes.py
from fastapi import FastAPI
app = FastAPI()

produtos = []
id_counter = 1

@app.post("/p")
def new(d: dict):
    global id_counter
    if not d.get("nome") or not d.get("preco") or d["preco"] <= 0:
        return {"e": "dados invalidos"}
    estoque = d.get("estoque", 0)
    if estoque < 0:
        estoque = 0
    p = {"id": id_counter, "nome": d["nome"], "preco": d["preco"],
         "estoque": estoque, "categoria": d.get("categoria", "geral")}
    produtos.append(p)
    id_counter += 1
    return p

@app.get("/p")
def all(cat=None):
    if cat:
        return [p for p in produtos if p["categoria"] == cat]
    return produtos

@app.get("/p/{id}")
def one(id: int):
    for p in produtos:
        if p["id"] == id:
            return p
    return {"e": "nao achei"}

@app.patch("/p/{id}/estoque")
def stock(id: int, d: dict):
    for p in produtos:
        if p["id"] == id:
            qtd = d.get("quantidade", 0)
            if p["estoque"] + qtd < 0:
                return {"e": "estoque insuficiente"}
            p["estoque"] += qtd
            return p
    return {"e": "nao achei"}

@app.delete("/p/{id}")
def rm(id: int):
    for p in produtos:
        if p["id"] == id:
            if p["estoque"] > 0:
                return {"e": "tem estoque, nao pode deletar"}
            produtos.remove(p)
            return {"ok": True}
    return {"e": "nao achei"}

O que fazer:

  • Criar schemas/produto.py com: ProdutoCreate, ProdutoResponse, EstoqueUpdate
  • Criar repositories/produto_repo.py que cuida do armazenamento (lista em memória por enquanto)
  • Criar services/produto_service.py com as regras de negócio (não pode deletar com estoque, estoque não pode ficar negativo)
  • Criar routers/produtos.py com as rotas usando nomes corretos (/produtos, não /p)
  • Criar main.py que só inicializa o app e registra o router

Entregar: exercicio3_antes.py + pasta exercicio3/ com os 5 arquivos separados
