Semana 1: TypeScript Avançado

Ingryd Aylana Silva dos Santos. React / TypeScript. Tempo estimado: 5 a 7 horas.

Você já sabe JavaScript nota 5 e já usa TypeScript. Esta semana não é sobre o básico. É sobre os 3 conceitos que separam "uso básico" de "domínio real": Generics, Utility Types e Discriminated Unions. Quando você domina esses conceitos, o editor vira seu melhor amigo e encontra bugs antes de você rodar o código.

Conceitos com exemplos

1. Generics (tipos genéricos)

Um generic é como um "espaço reservado" para um tipo. Você escreve a função uma vez, e na hora de usar, diz qual tipo vai ser. Em vez de criar várias funções iguais para tipos diferentes, você cria uma só.

// Sem generics: repetição desnecessária
function buscarUsuario(id: number): Promise<Usuario> {
    return fetch(`/api/usuarios/${id}`).then(r => r.json());
}
function buscarProduto(id: number): Promise<Produto> {
    return fetch(`/api/produtos/${id}`).then(r => r.json());  // código idêntico!
}

// Com generics: uma função que funciona com qualquer tipo
async function buscarPorId<T>(endpoint: string, id: number): Promise<T> {
    const resposta = await fetch(`${endpoint}/${id}`);
    return resposta.json();
}

// Na hora de usar, você diz o tipo entre < >
const usuario = await buscarPorId<Usuario>("/api/usuarios", 1);
const produto = await buscarPorId<Produto>("/api/produtos", 5);
// O TypeScript sabe que "usuario" é do tipo Usuario e "produto" é Produto

2. Utility Types (atalhos de tipos)

Você define uma interface uma vez e depois cria variações usando atalhos que o TypeScript já tem prontos. Assim não precisa copiar e colar campos toda vez que precisar de uma versão ligeiramente diferente.

interface Tarefa {
    id: number;
    titulo: string;
    descricao: string;
    concluida: boolean;
    criadaEm: Date;
}

// Partial: torna TODOS os campos opcionais
// Útil para formulários de edição (o usuário pode mudar só o título)
type TarefaUpdate = Partial<Tarefa>;
// Resultado: { id?: number; titulo?: string; descricao?: string; ... }

// Pick: pega SÓ os campos que você listar
// Útil para cards, previews, listas resumidas
type TarefaResumo = Pick<Tarefa, "id" | "titulo" | "concluida">;
// Resultado: { id: number; titulo: string; concluida: boolean; }

// Omit: remove os campos que você listar
// Útil para criação (o banco gera o id e a data)
type TarefaCreate = Omit<Tarefa, "id" | "criadaEm">;
// Resultado: { titulo: string; descricao: string; concluida: boolean; }

// Required: torna TODOS os campos obrigatórios (oposto de Partial)
type TarefaCompleta = Required<Tarefa>;

// Readonly: impede que qualquer campo seja alterado depois de criado
type TarefaCongelada = Readonly<Tarefa>;

3. Discriminated Unions (uniões discriminadas)

Quando uma variável pode ser de tipos diferentes dependendo de uma condição. O TypeScript usa um campo em comum (o "discriminador") para saber automaticamente quais campos existem.

// Uma resposta de API pode ser sucesso OU erro
// O campo "status" é o discriminador

type Sucesso<T> = {
    status: "sucesso";
    dados: T;
    total: number;
}

type Erro = {
    status: "erro";
    mensagem: string;
    codigo: number;
}

type ApiResponse<T> = Sucesso<T> | Erro;

// Quando você verifica o status, o TypeScript sabe quais campos existem
function tratarResposta<T>(resposta: ApiResponse<T>): T {
    if (resposta.status === "sucesso") {
        // Aqui o TS sabe que resposta tem .dados e .total
        console.log(`Total: ${resposta.total}`);
        return resposta.dados;  // autocomplete funciona!
    } else {
        // Aqui o TS sabe que resposta tem .mensagem e .codigo
        throw new Error(`Erro ${resposta.codigo}: ${resposta.mensagem}`);
    }
}

Exercícios da Semana

Três exercícios, do mais simples ao mais completo. Cada um trabalha um conceito diferente.

1 Exercício Fácil: Utility Types na prática Fácil

Crie o arquivo exercicio1_utility_types.ts com o seguinte:

// Dada esta interface:
interface Evento {
    id: number;
    titulo: string;
    descricao: string;
    data: Date;
    local: string;
    capacidade: number;
    organizador: string;
    ativo: boolean;
}

Criar estes tipos derivados (sem repetir campos):

  • EventoCreate: tudo menos id (o banco gera)
  • EventoUpdate: todos os campos opcionais (formulário de edição)
  • EventoCard: só titulo, data, local (card de preview)
  • EventoAdmin: tudo obrigatório, incluindo campos que poderiam ser opcionais
  • EventoPublico: tudo menos organizador e capacidade (o público não precisa ver esses dados)

Depois, crie uma variável de cada tipo com dados de exemplo para provar que os tipos funcionam.

Entregar: exercicio1_utility_types.ts

2 Exercício Intermediário: Generics para fetch tipado Intermediário

Crie o arquivo exercicio2_generics.ts com:

Parte A: Uma função genérica buscarDados<T> que:

  • Recebe um endpoint (string) como parâmetro
  • Faz fetch e retorna os dados tipados como Promise<T>
  • Trata erro de rede (try/catch) e retorna null se falhar

Parte B: Uma função genérica filtrar<T> que:

  • Recebe uma lista de itens (T[]) e uma função de filtro ((item: T) => boolean)
  • Retorna os itens que passam no filtro
  • Funciona com qualquer tipo (Usuario, Produto, Tarefa, string, number...)

Parte C: Uma função genérica agruparPor<T> que:

  • Recebe uma lista de itens (T[]) e o nome de um campo (keyof T)
  • Retorna um objeto agrupado por aquele campo
  • Exemplo: agruparPor(produtos, "categoria") retorna { "eletrônicos": [...], "roupas": [...] }

Demonstre cada função com pelo menos 2 tipos diferentes.

Entregar: exercicio2_generics.ts

3 Exercício Avançado: Sistema de notificações tipado Avançado

Crie o arquivo exercicio3_notificacoes.ts com um sistema completo de notificações usando discriminated unions + generics + utility types juntos.

Tipos de notificação (cada uma com campos diferentes):

// Cada tipo de notificação tem campos específicos.
// O campo "tipo" é o discriminador.

// tipo "mensagem": tem remetente, conteudo, lida
// tipo "alerta": tem severidade (info/warning/error), mensagem
// tipo "tarefa": tem titulo, prazo (Date), prioridade (alta/media/baixa), concluida
// tipo "sistema": tem acao, detalhes (opcional)

// Todas compartilham: id (number), criadaEm (Date), destinatario (string)

O que criar:

  • Interface base NotificacaoBase com os campos compartilhados
  • 4 interfaces específicas que estendem a base (uma por tipo)
  • Union type Notificacao que pode ser qualquer uma das 4
  • Função processarNotificacao(n: Notificacao): string que retorna uma mensagem diferente dependendo do tipo (use switch com discriminated union)
  • Função genérica filtrarPorTipo<T extends Notificacao>(lista: Notificacao[], tipo: string): T[] que filtra a lista pelo tipo
  • Tipos derivados: NotificacaoResumo (Pick com id, tipo, criadaEm) e NotificacaoUpdate (Partial da base)

Crie um array com pelo menos 6 notificações de tipos variados e demonstre todas as funções.

Entregar: exercicio3_notificacoes.ts
