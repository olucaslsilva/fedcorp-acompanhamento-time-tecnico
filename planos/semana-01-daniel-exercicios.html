Semana 1: Code Review

Daniel Mello de Carvalho de Faria. Node.js / Fullstack. Tempo estimado: 5 a 7 horas.

Code review é ler código que outra pessoa escreveu e dar feedback antes que ele entre no projeto. É assim que times profissionais garantem qualidade. E é uma das formas mais rápidas de evoluir, porque te obriga a pensar criticamente sobre cada decisão no código.

Conceitos com exemplos

1. O que procurar em uma review

Quando você lê código para fazer review, está procurando 5 coisas:

CategoriaPergunta que você fazExemplo de problema
Funciona?O código faz o que deveria? Cobre os casos extremos?Endpoint aceita quantidade negativa sem validar
Seguro?Tem vulnerabilidade? Dados são validados?Query SQL montada com template string (SQL injection)
Claro?Outro dev entende sem perguntar pra quem escreveu?Variáveis chamadas d, x, tmp
Eficiente?Tem algo que vai ficar lento com muitos dados?Buscar TODOS os registros do banco pra retornar só um
Testável?Feature nova tem teste? Bugfix impede que o bug volte?Endpoint novo sem nenhum teste

2. Como classificar problemas por severidade

SeveridadeSignificaExemplo
CRÍTICOVulnerabilidade de segurança ou bug que causa perda de dadosSQL injection, credencial exposta, dados sendo apagados sem confirmação
IMPORTANTEVai causar problema em produção mas não é de segurançaSem tratamento de erro (app crasha), query que busca tudo sem paginação
MENORQualidade de código, manutenibilidade, padrõesNomes genéricos, falta de tipagem, código repetido

3. Exemplo completo de review

Código enviado para review:

// Endpoint de cadastro de clientes
app.post("/clients", async (req, res) => {
    const q = `INSERT INTO clients (name, email, phone)
               VALUES ('${req.body.name}', '${req.body.email}', '${req.body.phone}')`;
    const r = await db.query(q);
    const all = await db.query("SELECT * FROM clients");
    res.json(all.rows);
});

Review feita:

CRÍTICO SQL Injection. A query usa template string direto com dados do req.body. Se alguém enviar name: "'; DROP TABLE clients; --", apaga a tabela inteira. Correção: usar parameterized queries com $1, $2, $3.
CRÍTICO Sem validação de entrada. O endpoint aceita qualquer coisa no body. Se name vier vazio ou email sem @, vai pro banco sem filtro. Correção: validar campos obrigatórios antes de inserir.
IMPORTANTE Sem tratamento de erro. Se o banco estiver fora, a aplicação crasha sem mensagem útil. Correção: envolver em try/catch e retornar status 500.
IMPORTANTE Query desnecessária. Após inserir um cliente, busca TODOS os clientes do banco. Se tem 100.000 registros, trava a resposta. Correção: retornar apenas o cliente criado com RETURNING *.
MENOR Nomes genéricos. q, r, all não dizem nada. Correção: insertQuery, result, clienteCriado.
MENOR Sem status code. Retorna 200 por padrão, mas deveria ser 201 (Created). Correção: res.status(201).json(...).

Código corrigido:

app.post("/clients", async (req, res) => {
    try {
        const { name, email, phone } = req.body;

        if (!name || name.trim().length < 2) {
            return res.status(400).json({ erro: "Nome é obrigatório (mínimo 2 caracteres)" });
        }
        if (!email || !email.includes("@")) {
            return res.status(400).json({ erro: "Email inválido" });
        }

        const resultado = await db.query(
            "INSERT INTO clients (name, email, phone) VALUES ($1, $2, $3) RETURNING *",
            [name.trim(), email.trim(), phone || null]  // parameterized, sem injection
        );

        res.status(201).json(resultado.rows[0]);  // 201 Created, só o novo
    } catch (error) {
        res.status(500).json({ erro: "Erro interno ao cadastrar cliente" });
    }
});

Exercícios da Semana

Três exercícios, do mais simples ao mais completo. Cada um é um endpoint com problemas que você precisa identificar, classificar e corrigir.

1 Exercício Fácil: Review de endpoint de busca Fácil

Faça a review do código abaixo. Identifique todos os problemas, classifique por severidade, e escreva a versão corrigida.

// Arquivo: exercicio1_review.ts
// Endpoint de busca de produtos por nome

app.get("/search", async (req, res) => {
    const x = req.query.q;
    const r = await db.query(`SELECT * FROM products WHERE name LIKE '%${x}%'`);
    res.json(r.rows);
});

O que entregar:

  • exercicio1_review.md: liste cada problema com severidade (CRÍTICO / IMPORTANTE / MENOR), explique o risco, e sugira a correção
  • exercicio1_corrigido.ts: o código reescrito com todos os problemas resolvidos

Dica: esse código tem pelo menos 4 problemas. Se encontrou menos, olhe de novo.

2 Exercício Intermediário: Review de endpoint de autenticação Intermediário

Este endpoint é mais perigoso porque lida com dados de login. Faça a review completa.

// Arquivo: exercicio2_review.ts
// Endpoint de login

const SECRET = "minha-chave-secreta-123";   // chave JWT

app.post("/login", async (req: any, res: any) => {
    const user = await db.query(
        `SELECT * FROM users WHERE email = '${req.body.email}'
         AND password = '${req.body.password}'`
    );

    if (user.rows.length > 0) {
        const token = jwt.sign(user.rows[0], SECRET);
        res.json({ token: token, user: user.rows[0] });
    } else {
        res.json({ error: "login failed" });
    }
});

O que entregar:

  • exercicio2_review.md: a review completa (esse código tem pelo menos 7 problemas, incluindo problemas graves de segurança)
  • exercicio2_corrigido.ts: o código reescrito

Dica: pense em segurança de senhas, o que acontece se o JWT incluir a senha, e o que a resposta de erro revela.

3 Exercício Avançado: Review completa de módulo de pedidos Avançado

Agora o desafio completo. Um módulo inteiro com 3 endpoints. Faça a review de cada um, classifique, corrija, e reorganize.

// Arquivo: exercicio3_review.ts
// Módulo de pedidos (orders)

var pedidos: any[] = [];
var id = 1;

app.post("/order", (req: any, res: any) => {
    var o: any = {};
    o.id = id;
    id = id + 1;
    o.client = req.body.client;
    o.items = req.body.items;
    o.total = 0;
    for (var i = 0; i < o.items.length; i++) {
        o.total = o.total + o.items[i].price * o.items[i].qty;
    }
    o.status = "pending";
    o.date = new Date();
    pedidos.push(o);
    console.log("Pedido criado: " + JSON.stringify(o));
    res.send(o);
});

app.get("/orders", (req: any, res: any) => {
    res.send(pedidos);
});

app.put("/order", (req: any, res: any) => {
    for (var i = 0; i < pedidos.length; i++) {
        if (pedidos[i].id == req.body.id) {
            pedidos[i].status = req.body.status;
            res.send(pedidos[i]);
            return;
        }
    }
    res.send({ error: "not found" });
});

O que entregar:

  • exercicio3_review.md: review dos 3 endpoints com pelo menos 10 problemas no total, cada um com severidade e sugestão de correção
  • Pasta exercicio3_corrigido/ com a versão reescrita, organizada em:
    • types/pedido.ts (interfaces tipadas)
    • routes/pedidos.ts (rotas com nomes corretos e tipagem)
    • services/pedido.service.ts (lógica de negócio separada)

Dica: procure problemas de tipagem (any em tudo), variáveis com var em vez de const/let, comparação com == em vez de ===, falta de validação, falta de status codes corretos, console.log em produção, e rota PUT sem o id na URL.
